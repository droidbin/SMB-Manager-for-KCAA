# SMB Manager 2.0.0-beta.1 — 부서 내부 시험 전용

공개 베타 채널에 게시하지 않는 수동 설치 후보입니다. 기존 1.7.x의 자동 업데이트 대상이 아닙니다. 포터블 배포는 제공하지 않습니다.

## 설치·분리

- Windows x64 MSI를 관리자 권한으로 설치합니다. 시작 메뉴의 `SMB Manager Internal Beta 1 관리자`와 `클라이언트`를 사용합니다.
- 설치 경로: `C:\Program Files\SMB Manager Internal Beta 1`.
- 설정·장치 키: `%LOCALAPPDATA%\SMB Manager Internal Beta 1`. 현재 Windows 사용자 DPAPI로 보호하므로 다른 PC나 사용자에게 복사해 배포하지 않습니다.
- 기존 알파 및 1.7.x 설치·설정은 자동 이관하지 않습니다. 관리자 프로그램을 닫으면 해당 관리 서버도 종료됩니다. 관리 PC는 시험 동안 로그인과 앱 실행을 유지해야 합니다.
- 같은 PC에서 기존 연결 프로그램과 베타가 같은 드라이브 문자를 동시에 관리하지 않도록 합니다. 첫 시험은 비어 있는 드라이브 문자와 별도 시험 공유폴더로 시작합니다.

## 관리자 PC 설정

1. 관리자 프로그램을 한 번 실행하고 종료해 설정 디렉터리를 만듭니다. 기본 관리 API는 `http://127.0.0.1:48751/`이며 관리자 기능은 서버 PC에서만 사용합니다.
2. 다른 PC의 클라이언트를 연결하려면 관리자 Windows 사용자의 개인 인증서 저장소에 개인 키·서버 인증 EKU가 포함된 유효한 HTTPS 서버 인증서가 필요합니다. 코드 서명 인증서와는 별개입니다.
3. 위 설정 디렉터리의 `server\https.json`에 실제 IP·포트·인증서 지문을 설정합니다. 아래 값은 예시이며 그대로 사용할 수 없습니다.

```json
{"bindAddress":"192.0.2.10","port":48753,"certificateThumbprint":"실제 서버 인증서 지문"}
```

4. 관리자를 다시 실행합니다. 클라이언트에는 인증서 이름과 일치하는 `https://실제서버DNS이름:48753/` 주소를 입력합니다. 모든 시험 PC에서 인증서 신뢰·이름·기간 검증을 통과해야 합니다. 인증서 검증 우회는 제공하지 않습니다.
5. 필요한 경우 조직 관리자가 방화벽에서 시험 부서의 클라이언트 주소 범위에만 해당 포트를 허용합니다. 이 설치본은 방화벽·인증서 신뢰·보안 프로그램 설정을 자동 변경하지 않습니다.
6. 관리자에서 등록 코드를 발급하고 클라이언트를 등록합니다. 관리자가 PC 등록을 승인한 뒤 부서, Drive 계정, 허용 공유폴더를 배정합니다. 직원의 부서 선택이나 연결별 로컬 승인 없이 정책이 적용됩니다.
7. Drive 암호를 서버가 배포하지 않습니다. 시험 Windows 사용자에게 기존 공유 서버 자격 증명이 준비되어 있어야 합니다. 관리자 배정과 실제 연결 계정의 일치를 확인합니다. 실제 읽기·쓰기 권한은 공유 서버 ACL을 기준으로 확인합니다.

## 시험 순서와 중단 기준

우선 관리자 1대·시험 클라이언트 1대로 등록 → 승인 → 배정 → 연결 → 시험 파일 읽기/쓰기 → 연결 해제/재연결 → 알림 → 앱 재시작 → 배정 회수를 확인합니다. 새 작업 전에 업무 파일을 저장합니다. 기존 연결 손상·계정 불일치·보안 제품 탐지·반복 종료·UI 잘림이 발생하면 추가 PC 확산을 중단합니다.

부서 내 확대 시험은 실제 72시간과 업무 집중 시간대를 포함합니다. Windows 재부팅 후 수동 실행, 관리 서버 중단/복구, 다른 부서 공유 접근 거부, 창 크기·125/150/200% 배율, 설치·제거·재설치도 확인합니다. 로그인 자동 실행·서비스 설치는 없습니다.

AhnLab Safe Transaction, TouchEn, nProtect, INISAFE, VeraPort 및 사용하는 은행·카드·홈택스에서 동시 실행을 시험합니다. 알약·안랩·Defender 호환성을 제품별로 판정합니다. 금융 인증·거래는 사용자가 수행하고 비밀번호·계좌·인증서를 QA 기록에 담지 않습니다. 보안 프로그램의 제외 등록이나 중지를 해결책으로 사용하지 않습니다.

## 현재 한계

- 미서명 후보이며 모든 보안 제품의 무탐지·호환성을 보장하지 않습니다.
- 전용 탐지 파일 감시와 앱 소유 드라이브 해제는 부분 차단입니다. 일반 랜섬웨어 탐지·전체 네트워크 격리 기능이 아닙니다. 직접 UNC 접근이나 외부 프로그램의 연결까지 차단하지 않습니다.
- 구버전 부서 자동 이관·MAC 수집은 미구현입니다. 관리자가 배정합니다.
- 알파 시험 결과를 베타의 동일 파일 검증 결과로 간주하지 않습니다. 정확한 MSI 해시의 VM 확인 결과와 실제 부서 시험 기록을 구분합니다.

## 복구

관리자에서 시험 PC의 허용 공유를 회수하고 앱 소유 매핑이 해제되는지 확인한 뒤 클라이언트를 종료합니다. 오류가 있으면 외부 연결을 일괄 삭제하지 말고 상태를 기록합니다. Windows 설치된 앱에서 내부 베타만 제거합니다. 사용자 설정은 복구를 위해 남깁니다. 기존 1.7.x 설정·저장 자격 증명은 덮어쓰지 않습니다. 서버 키·프로필·배정 저장소는 동일 사용자 문맥에서 함께 백업합니다.
