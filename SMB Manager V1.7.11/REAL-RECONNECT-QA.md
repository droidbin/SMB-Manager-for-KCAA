# 1.7.11 핫픽스 실행 검증

검사일: 2026-10-18 KST

## 설치 및 실행

실제 배포용 Setup.exe의 설치 버튼과 완료 확인을 거쳐 이 PC를 1.7.10에서 1.7.11로 업그레이드했다. 기존 설치 폴더를 백업했으며 설치본 EXE와 배포 EXE의 SHA-256 일치 및 설치 후 앱 실행을 확인했다.

## 실제 NAS 시험: 18 / 18 통과

설치된 1.7.11의 실제 타이머와 NAS를 사용했다. 원래 업무용 드라이브 6개는 유지하고 임시 매핑만 사용했다. 시험 중 15초 주기로 확인한 후 원래 60초로 복원했다.

관측 간격은 0.5초다. Windows 네트워크 API 응답 시간과 진행 중 작업 중복 방지에 따라 실제 재시도 간격이 점검 주기와 정확히 일치하지 않을 수 있다.

## 기존 사용자 업데이트 호환

원본 1.7.10 바이너리의 실제 릴리스 선택/버전 비교 코드를 실행해 정식 채널과 베타 포함 채널 모두 1.7.11을 선택하는 것을 확인했다. GitHub가 ZIP 이름의 공백을 점으로 바꾸는 형식도 인식했다. 자동 업데이트 확인 전용 팝업을 실제로 열고 확인 반환 경로를 실행했다.

기존 1.7.10은 시작 시 업데이트를 조회한다. 이미 실행 중인 앱에 서버가 즉시 푸시하거나 자동 업데이트를 꺼 둔 사용자에게 무인 강제 설치하는 기능은 없다. 설치 프로그램의 설치 단계도 필요하다.

## 재현과 증거

- 재현: source/test-real-reconnect.ps1 -ClientVersion 1.7.11
- NAS 결과: 저장소 .build-logs/real-reconnect-20261018-135019/report.json
- 설치 결과: .build-logs/install-1.7.11-20261018-135002/report.json
- 이전 클라이언트 팝업 결과: .build-logs/update-prompt-result.txt
- 실제 클라이언트 로그: 사용자 AppData/Roaming/SMB Manager/result.log

초기 시험에서는 Windows에 남은 이전 드라이브 정보 때문에 없는 공유 시험이 매핑 보존 검사로 처리됐다. 최종 시험은 Windows API로 매핑 기록이 없는 문자를 선택하고 실제 오류 67을 두 번 확인하도록 보완했다.
