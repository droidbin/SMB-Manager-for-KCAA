## 테스트와 정식 전환 기준

- 단계는 **베타 → 정식**입니다. 베타는 내부 Windows 10/11 VM과 부서원 대상 시험입니다.
- 통과율 = 핵심 QA 필수 세부 항목 통과 수 ÷ 적용되는 전체 필수 세부 항목 수 × 100.
  - Windows 10/11은 각각 집계합니다.
  - 실패·미실행·차단은 통과로 세지 않습니다.
- 정식 전환 조건: 통과율 90% 이상, 그리고 다음을 모두 확인해야 합니다.
  - 중대 개인정보·인증·데이터 손실 문제가 없음
  - 설치본 서명·무결성과 복구 준비
  - 실제 업데이트 전달
- 직원 앱 핵심 QA:
  - CB01 실제 설치·설정 보존
  - CB02 별도 서버 실제 연결·권한·파일 작업
  - CB03 변경 영향·중대 문제 검토
  - CB04 서명·무결성·복구
  - D01 GitHub·인증 전달
  - D02 실제 업데이트·연결
- 관리자 앱은 지정된 Windows 11 관리자 PC에서 실제 설치, 서버 운영·인증, 영향 검토, 서명·복구, 전달을 확인합니다.

### 2.0.8 정식 전환 기록 (2026-11-07)

- 시험PC의 Windows 10/11 VM에서 확인한 항목:
  - 실제 업데이트와 등록 보존
  - 별도 SMB 서버의 계정·파일 작업·미배정 거부
  - 정식 2.0.6 → 2.0.8 전달
  - 실제 1.7.7·1.7.11 설치 → 2.0.8 직접 업데이트
  - 관리자 강제 업데이트 실측(10분 안내 → 자동 설치 → 앱 재실행 → 완료 보고)
- 관리자 PC에 관리자 2.0.8을 실제로 설치했습니다. 운영 데이터, 인증, 채널이 보존됐습니다.
- 핵심 QA 72/78(92.3%), 실패 0으로 정식 전환했습니다. 운영 반영 후 77/78입니다. 남은 1개는 운영에서 실행하지 않는 권한 철회 시험입니다.
- 시험 중 발견한 결함 두 가지를 수정한 뒤 배포했습니다.
  - 업데이트 서비스로 설치를 넘기는 단계의 메시지 형식 오류
  - 1.7.7이 관리자 ZIP을 먼저 고르는 문제

## 배포 원칙

- 최종 MSI·zip은 GitHub Releases로만 제공합니다. 같은 자산 이름에 다른 바이트를 올리지 않고, 수정본은 새 버전·빌드로 게시합니다.
- 빌드 성공은 QA 승인이 아니며, GitHub 게시는 앱 내 전달 성공을 뜻하지 않습니다. 앱 전달은 GitHub에서 다시 받아 확인한 동일 파일을 회사 관리 서버 카탈로그에 반영한 뒤 인증된 다운로드로 확인합니다.
- 비공개 서버 데이터·암호·토큰·개인키·복구본은 저장소와 릴리스에 올리지 않습니다.
- 정식 전환 전 GitHub 게시는 Latest가 아닌 상태(프리릴리스)로 전달을 검사한 뒤 Latest로 전환합니다.

## 사용 범위

사내 업무용 배포 및 소스 이력 저장소입니다. 개인·외부 기관·기업 대상 업데이트를 제공하지 않습니다. 별도의 프로젝트 오픈소스 라이선스를 새로 부여하지 않았습니다. 폰트 등 제3자 자산의 안내는 해당 자산 폴더에 있습니다.
