# 기존 2.0 정식 사용자의 r4 업데이트 인식

2026-11-04 사용자 승인: “내부 파일 버전만 올려서 적용”. 제품 표시 버전 **2.0.5**, MSI 버전 **2.0.145**를 유지하고 내부 파일 버전을 **2.0.145.1**로 올렸다. 메타데이터만 높은 버전으로 꾸미지 않고 실제 서명 DLL/EXE와 카탈로그 버전을 일치시켰다.

기존 앱은 `BetaUpdate.Compare`에서 파일 버전을 우선 비교한다. 출시된 build37의 원본 Contracts.dll(SHA256 `3D8BBF061ABD034C2DCED445766D7C1D79CFAAE4BBE5E3B0911DF2F84E1C40DE`)을 두 전용 VM에서 실제 인증 응답과 함께 호출해 .145.0→.145.1은 `1`, 설치 후 .145.1은 `0`, 더 높은 .146.0은 `-1`을 반환함을 확인했다. 원본 비교 코드를 변경하거나 기존 사용자에게 선행 패치를 요구하지 않는다.

## 정확한 설치본과 전달

- 파일: `SMB-Manager-Client-2.0.5-Patch-r4-x64.msi`
- SHA256: `CB2AB9932EB9F151B43DB980F956651CA55EF61DC6D65AEC7C67DB175753E0F8`
- 소스 커밋: `0f641e1b7568a4e01d0959fe615e3b5d08bd9cbf`
- 설치된 ClientDesktop.dll SHA256: `B24B1D40E065179AD78F53C14340423E0FD2BABC40A03DC40E109F4EB10AE26F`
- 서명: KCAA(LEE HYEONGBIN), 검증 상태 Valid
- [정식 릴리즈](https://github.com/droidbin/SMB-Manager-for-KCAA/releases/tag/v2.0.5-patch-r4)

Windows 10/11에서 원본 build37 MSI를 실제 설치한 뒤 GitHub 검증 파일을 인증된 시험 카탈로그로 새로 받아 업데이트했다. 파일 복사나 설치 표시용 fixture로 이전 버전을 꾸미지 않았다. 두 OS 모두 .145.0→.145.1 설치 종료 코드 0, 정확한 새 DLL, 일반 사용자 설치 완료, 장치 ID/키·공개 키·서버 주소·성명·부서·PC명 보존을 확인했다. 이후 실제 매핑과 지정 파일 읽기/쓰기/삭제, 별도 Samba 서버의 인증 계정을 확인했다.

현재 중앙 정책의 직원 클라이언트 필수 CB01/CB02/CB03/CB04/D01/D02 세부 검사는 OS별 27개, 총 **54/54(100%)**다. 개별 원장·정확한 행렬·설치본·정책 해시에 묶은 `delivery`와 `public` 최종 게이트가 모두 승인됐다. 순수 규칙 검사 22개나 반복 실행을 분모/분자에 추가하지 않았다. 변경 영향이 없는 권한·복구 및 r3 재실행 증거는 원래 해시와 소스 적용 근거로 재사용했다.

정식 Latest 전환 후 실제 관리자 물리 저장소의 두 호환 카탈로그에 같은 r4와 파일 버전을 반영했다. 백업 이후 동시 변경 여부, 불변 파일명 충돌, 실제 물리 경로를 검사했고 원래 파일과 복구 사본을 보존했다. 서버 재시작과 기기 배정·승인·채널 권한 변경은 없었다. 운영 HTTPS 경로에서 허용된 계정의 전체 다운로드 SHA256/서명이 GitHub와 일치했다. 해당 계정에 비허용인 closed-beta는 기존대로 403이며 다운로드 성공으로 세지 않았다. 채널 선택과 실행 중인 운영 앱도 변경하지 않았다.

## 보존한 실패와 한계

GitHub 게시 전에는 사전 핵심 38/54만 완료됐고 자동 승인 검토가 배포 QA 미완료를 이유로 게시를 차단했다. 사용자가 정확한 r4의 베타 게시 후 전달 QA를 명시적으로 승인했고, 이후 남은 실제 전달 검사를 수행했다. 이 예외 자체를 Pass로 바꾸지 않았다.

첫 전달 메타데이터 요청은 전용 시험 관리 서버가 중지돼 시간 초과했다. 시험 서버를 확인·시작하고 실패 구간만 재개했다. 불완전했던 첫 운영 백업과 GitHub 정식 전환의 HTTP 500도 보존했고, 상태 확인 후 미완료 부분만 진행했다. [이전 r1/r2 MSI 실패](PATCH-2.0.5-REVIEW-2026-11-04.md)는 그대로 남겼다.

실제 UAC 비활성 데스크톱이나 새 재부팅을 직접 측정한 것으로 주장하지 않는다. 유지보수 UAC 취소 후 수동 재실행이 필요할 수 있다. 확장 전체 캠페인과 관리자/서버 패키지는 이번 클라이언트 배포의 통과 범위가 아니다.

신규 stable/beta 서버 프로토콜 전환과 이번 기존 사용자 업데이트 인식은 별개다. 기존 호환 채널 키·접근 제한을 유지했으며 베타 카탈로그를 이름만 바꿔 정식으로 승격하지 않았다.
